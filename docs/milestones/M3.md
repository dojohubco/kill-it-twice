- ES05: exactly 500 real events staged through bounded capture, one 500-item bulk, 497 applied and three actual mapping rejections; durable dead letters; no resend of terminal work; a new source revision repairs current state without rewriting the old failure.
- ES06: identical restaging preserves pending, leased, retry_wait, satisfied and dead_letter ES state and history; missing relations fail; capture restages after ES settlement.
- ES07: real SIGKILL at all three private boundaries, independently observed durable state, recovery and healthy release controls.
- ES08: real Toxiproxy downstream loss after upstream application; independent direct realtime GET; unknown response becomes retryable, then equal replay resolves safely.
- ES09: expired A lease while request outstanding, B higher generation settles, resumed A cannot overwrite B; independent database-clock evidence.
- ES10: owned ES service stopped for at least 60 measured seconds; capture progresses; bounded shared cooldown/probes; automatic recovery, exact attempt timeline.
- ES11: runtime creation/deletion/rebinding denied, controlled same-name UUID replacement/config mismatch detected, bad credentials block without mass dead letters.
- ES12: request/record/response bounds and invalid correspondence fail closed; lossless version parser negative fixtures are supplemental.
- ES13: populated guarded M2C.1 upgrade preserves event bytes, IDs, creation times, source ACKs, RabbitMQ/consumer rows while ES alone progresses.
- ES14: independent finite reconciliation, missing/extra/corrupt receiver negative controls, retained restart of three services preserves IDs/data, scoped cleanup.

Every case must execute and pass, with no skip/todo/cancel/duplicates. Executable inventory will implement these independently recorded requirements; the timing is not a fictional test-first execution history. A protocol failure is retained before choosing any supported correction.

## Scope and verification

Use a forward pipeline migration, accepted TransactionOwner, immutable canonical eleven-field envelope and existing capture bounds. No source migration or business-command retry. The 500-item ES test accumulates ordinary small capture batches; it never enlarges source transfer limits. Make verify-m3 will run prior profiles once, then fresh ES and populated-upgrade acceptance. Repeat the complete gate once from committed code and a clean tracked tree. Full verify remains nonzero for G1-G5. Evidence includes exact SQL/receiver observations, signals, attempts, network loss, outage times, cleanup, input hashes and a compact tracked summary; full dumps stay in ignored review artifacts.

Stop after M3. No RabbitMQ delivery/consumer, seed/activation, backfill, replay API, UI, deployment or scale claim.
