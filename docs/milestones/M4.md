## Design and limits

[ADR 011](../adr/011-rabbitmq-consumer.md) specifies the additive pipeline and independent consumer SQL boundaries, privileges, fixed topology and protocol. Existing canonical bytes, eleven fields, precision codec, source command semantics, capture ACK and Elasticsearch behavior do not change. Source ACK means staged; broker-confirmed means accepted by the broker; consumer processed means its independent database transaction committed. None implies the other automatically.

Select RabbitMQ 4.3.6-management, pulled before implementation at sha256:de62d9901fb73aaa8767b9c1e9ea32f2938f69d1b83e430f7c5ca854081d2128, and amqplib 2.0.1 with bundled TypeScript types. Pull/npm metadata are availability evidence, not protocol acceptance. Real startup, TLS, permissions, confirms, mandatory returns, overflow and crash retention must be tested. All previous pins stay fixed. The existing Toxiproxy supplies real connection faults.

Starter bounds: 128 unconfirmed publications/4 MiB, 10 s confirmation deadline, 30 s SQL leases renewed near 5 s, 15 s AMQP heartbeat, 128 KiB broker message cap; consumer prefetch 64, one active transaction, at most 32 messages/1 MiB or 25 ms flush. Queue ready-body budget is 16 MiB with reject-publish, not an exact total disk/memory budget. Test timing changes must be explicit. SQL generations/IDs remain exact BIGINT decimal strings.
