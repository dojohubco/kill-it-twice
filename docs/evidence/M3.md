## Contract and implementation

[ADR 010](../adr/010-elasticsearch-projection-delivery.md) and the dated SPEC refinement define search-v1 and durable item outcomes. Source migrations 001–005 and pipeline migrations 001/002 remain unchanged. The eleven-field event, PG18 codec, canonical bytes/hash, business command idempotency, transaction owner and capture/ACK semantics remain unchanged. The only production schema addition is forward pipeline [003-elasticsearch.sql](../../migrations/pipeline/003-elasticsearch.sql).

The existing ES delivery intent now has fenced leases and pending/leased/retry_wait/satisfied/dead_letter states. One target record retains immutable registration and bounded cooldown/probe state; bounded attempts and immutable dead letters reference original events. Composite FKs, checks, deferred evidence/obligation constraints and allowlisted SECURITY DEFINER functions protect local transitions. RabbitMQ and consumer rows stay pending and unchanged. Staging tests require structural obligations while preserving progressed ES states; missing evidence still fails closed.

Workers commit claims before network I/O and use separate owners for renewal and per-item settlement. Database time is checked after locks, BIGINT generations never enter Number, and stale claims cannot rewrite outcomes. One request per worker is in flight; 500 operations, 4 MiB request/response and 256 KiB projected-operation bounds are independent of the retained 16-record/256-KiB capture bounds. Defaults remain 10-second requests, 30-second leases, renewal around 5 seconds and persisted positive exponential jitter capped at 30 seconds. Shared cooldown admits one fenced probe. Request opaque IDs use a retained anchor attempt UUID. Short lease timings are only explicit fault fixtures; ordinary M3 capture uses production timings.

PostgreSQL extracts optional top-level name/country/loyalty_points directly as JSON text. The complete canonical body is stored as an exact string in normal `_source`; unindexed arbitrary-precision fields remain present. Strict integer mapping receives incompatible tokens and rejects them on the real server. Strict `external` versions protect full-state indexing and indexed tombstones; ordinary delivery uses neither physical DELETE, update/upsert nor `external_gte`.

An HTTP 200 bulk response is parsed completely, including every identity/item/error. Confirmed valid items settle independently. Conflict resolution uses realtime GET, exact remote version and the full actual projection against a retained local revision, not a copied hash. Equal matching state is already_applied; matching known higher state is superseded. Timeout/unknown application stays retryable; bad credentials/configuration/integrity block the target, not a mass DLQ. Genuine mapping rejection retains the original failure; a corrected source command creates a different revision.

Initialization binds a unique concrete index's real cluster/index UUIDs and verified mapping/settings configuration, using setup credentials separate from runtime. Runtime uses a file-realm user and role whose private configuration is retained alongside the data volume. Controlled setup uses the pinned server password tool and an initialization restart; no worker needs admin access or depends on native security-index recovery for authentication. Startup cluster identity `_na_` admits no write and is retryable; an established different UUID still blocks. Runtime has exact index/bulk action grants plus reads/metadata for that one index, with only cluster UUID access. Mapping/index/security administration, document deletion and target rebinding are denied. The extra isolated raw bulk delete/update probe also returned actual 403s and retained its document; its script, input hash and results are in the bundle. TLS CA verification is enabled, automatic index creation/retries/sniffing are disabled, and workers cannot set up a target.
