# ADR 009: bounded incremental capture and staged acknowledgement

Status: implemented and locally verified in M2C; see [acceptance evidence](../evidence/M2C.md). The original design and executable inventory were committed before production changes. Origin: the already planned capture/ACK boundary, refined for M2C on 2026-09-17. No full G1–G5 guarantee.

## Identity and initialization

Forward pipeline migration 002 adds `pipeline_id uuid NOT NULL UNIQUE DEFAULT gen_random_uuid()` to the immutable singleton pipeline.source_binding. It is migration-created once, independent of epoch/destination IDs, and survives retained storage restart. A SECURITY DEFINER read-only identity function returns pipeline ID, epoch and codec. A new pipeline_capture role can execute identity, identity-bound staging and sanitized incident recording only. Its staging function checks the supplied pipeline ID inside the actual READ COMMITTED staging transaction, then calls the existing stage_event. It cannot call the old unbound entry point. The existing pipeline_stager remains for M2B's explicitly selected local staging scope.

Forward source migration 004 creates source.capture_binding: singleton boolean PK constrained true; pipeline_id uuid NOT NULL UNIQUE; source_epoch uuid NOT NULL UNIQUE FK source_identity; payload_encoding text NOT NULL constrained pg18-jsonb-text/v1; registered_at finite timestamptz NOT NULL default clock_timestamp(); UNIQUE(pipeline_id,source_epoch). UPDATE/DELETE/TRUNCATE are forbidden. Registration is privileged initialization, never a worker operation. Read the pipeline identity, compare all three configured values, then register that exact identity on the source. A crash after the pipeline migration and before source registration leaves no claims/ACK opportunity. Repeating identical registration is harmless; different binding fails P4001. Independent rollback of retained databases is outside the guarantee.

The source migration installs an AFTER INSERT outbox trigger. Before registration it has no binding to enqueue; registration uses `LOCK TABLE source.outbox IN SHARE ROW EXCLUSIVE MODE`, inserts the singleton, and fills every retained outbox revision in the same READ COMMITTED transaction. That lock waits for existing outbox writers and excludes new INSERTs until registration COMMIT. A fresh statement after acquiring it sees prior committed revisions; later writers see the binding and enqueue atomically. This is a short controlled initialization pause, not a sequence watermark or baseline seeding. Installing the trigger uses ordinary transactional DDL locking. Already manually staged M2B revisions start pending and restage safely. A work insertion failure aborts source mutation/outbox together.

## Durable work and SQL surface

One source.capture_work row per retained mutation; no duplicate payload:

- work_id positive generated-always noncycling BIGINT PK for native scheduling order, not completeness;
- pipeline_id/source_epoch UUID NOT NULL composite FK capture_binding; entity_id/entity_version positive BIGINT NOT NULL, UNIQUE(source_epoch,entity_id,entity_version), composite FK outbox revision;
- state text NOT NULL restricted pending/leased/acknowledged/blocked;
- generation BIGINT NOT NULL default 0, nonnegative; owner_id UUID nullable, lease_until finite timestamptz nullable;
- next_eligible_at finite timestamptz NOT NULL default clock_timestamp(); reason text nullable, restricted transient_failure/oversized_record;
- acknowledged_hash nullable lowercase 64-hex text, acknowledged_at nullable finite timestamptz, acknowledged_generation nullable BIGINT.

Shape checks use explicit IS NULL/IS NOT NULL: pending and blocked have no owner/lease/ACK; blocked requires oversized_record; leased has owner, positive generation and deadline but no ACK; acknowledged retains owner and positive generation with identical acknowledged_generation, hash/time and no lease/reason. Pending can retain transient_failure and a delayed eligibility time. A guard forbids changing revision/binding/work identity, decreasing generation, deleting/truncating work, or changing any acknowledged row. Grants plus fixed control functions enforce transitions; raw owner bypass is excluded. Partial indexes cover (next_eligible_at,work_id) for pending and (lease_until,work_id) for leased.

`capture_claim(pipeline UUID, epoch UUID, owner UUID, count integer, lease_ms integer)` requires READ COMMITTED, validates binding and bounds, then selects due pending or expired leased rows ordered by work_id FOR UPDATE SKIP LOCKED LIMIT count. After locking, read clock_timestamp, increment generation (overflow errors 22003), assign owner/deadline and return at most 16 keys/tokens plus source times and SQL-measured escaped payload size. No payload crosses this call. Concurrent owners cannot share an unexpired claim. No maximum-ID filter exists.

`capture_change(pipeline UUID, epoch UUID, entity BIGINT, version BIGINT, owner UUID, generation BIGINT, action text, duration_ms integer, hash text)` locks the exact row first, then reads clock_timestamp. Missing work is P4003 integrity; wrong binding P4001; wrong/expired/noncurrent token P4002 stale. Renew extends a still-current lease; defer clears ownership and sets pending eligibility from the source clock; block clears ownership with oversized_record; acknowledge retains hash/time/generation/owner and clears lease. No expired claim can renew, defer, block or ACK, even before reassignment. An identical terminal ACK returns already_acknowledged without UPDATE; a different terminal hash is P4003, different owner/generation P4002. ACK validates shape/ownership, not remote durability.

`capture_summary(pipeline UUID, epoch UUID)` returns one fresh source timestamp and exact decimal-string counts for pending due/delayed, leased current/expired, blocked, acknowledged and missing work. Missing rows cause explicit integrity failure in the worker; unreachable source is unknown, never zero. Summary aggregation returns bounded metadata, not a history API.

source_capture is a separate nonprivileged NOINHERIT role: CONNECT/USAGE, EXECUTE only claim/change/summary, SELECT only source identity and required immutable outbox columns for the bounded adapter. No entities/receipts, mutation functions, raw work/binding writes, sequences, owner membership or capture alteration. All privileged functions are source_owner-owned SECURITY DEFINER with qualified references and pg_catalog,pg_temp search_path. PUBLIC EXECUTE revocation and grants occur in the same migration transaction.

## Three transactions and bounded loop

A: claim and confirm source COMMIT, closing its private session. B: transfer fitting immutable revisions and stage a sorted, deduplicated batch with the accepted owner and actual pipeline-ID check; confirm COMMIT and successful owner return. C: per-revision ACK under current claim in a new source transaction. Never hold A open across B or ACK inside B's work callback. Unknown or confirmed-commit/cleanup-error B results acknowledge nothing; explicit safe staging repetition resolves durable evidence. The business command owner still never retries mutations.

captureOnce uses a fresh process incarnation UUID and separate control/renewal owners. Defaults: 16 claims, 64 KiB record, 256 KiB batch, one batch in flight, 30 s lease, renewal about every 5 s, idle poll 1 s. Validated shorter test intervals do not change source-clock ownership. Partition claims by SQL-measured escaped payload plus the existing 1024-byte allowance before payload transfer. Oversized individual records become blocked, never ACKed; valid medium records split into fitting batches. Missing claimed revisions are integrity errors. Compare the complete returned unique event-ID set with submitted events before any ACK.

Renew outstanding claims on independent short source transactions while pipeline requests run. Lost ownership stops further local ACKs, without pretending to cancel remote requests. Renewal is stopped/drained before ACK transitions to avoid concurrent terminal updates; immediately revalidate current ownership through the ACK function. Bound every database operation using the accepted owner. Release still-owned work after transient failures using persisted exponential delay: 1 s base, 30 s cap, with nonzero randomized jitter. Infrastructure failure has no attempt cutoff or permanent block. Binding/canonical integrity failures stop the worker unacknowledged; diagnostics are bounded and secondary failures remain separate.

Explicit once/follow CLI modes use only the configured source/pipeline credentials and pipeline identity. Follow waits between empty/delayed observations, discovers new writes after idle, and emits bounded fresh-state reports. SIGTERM/SIGINT stop admitting work; current bounded operations settle or leave recoverable leases. SIGKILL safety requires no shutdown handler. An empty claim does not mean fully caught up when leased/delayed/blocked work exists.

## Independent validation and limitations

The executable IC01–IC16 inventory plus four IC11 healthy controls is committed with this design, before implementation or execution. Private test instrumentation pauses the actual production operations at capture.after_claim_commit.before_stage, capture.before_pipeline_commit, capture.after_pipeline_commit.before_source_ack and capture.after_source_ack_commit.before_success. Actual SIGKILL/service shutdown causes faults; independent observers establish source clocks, token generations, sessions/locks, exact bytes/hash/metadata/obligations and terminal ACKs. Healthy releases must return one success and close sessions. Prior profiles remain separate and unchanged; fresh and populated M2B upgrade capture profiles are required.

This is at-least-once source-to-pipeline staging, not publication or receiver/consumer success. Source SQL cannot inspect a remote COMMIT through a FK or digest: stage-before-ACK is a trusted capture protocol invariant tested with actual failures. Keep the eleven-field canonical envelope byte-for-byte unchanged. No payload/outbox rewrite, seeding/backfill/checkpoints/fences, sink worker, public replay API, general retry framework or full Optio gate.

Before real delivery, migrate M2B assert_obligations deliberately so valid settled obligations permit already-staged replay without resetting success; pending/unbound remains correct now. Preserve ADR 007's future regression: seed a protected baseline without mutation outbox, activate, unchanged update retains a successful command receipt without inventing a mutation. Neither future change is implemented by M2C.

References: [PostgreSQL clock semantics](https://www.postgresql.org/docs/18/functions-datetime.html#FUNCTIONS-DATETIME-CURRENT), [row locking and SKIP LOCKED](https://www.postgresql.org/docs/18/sql-select.html), [table lock conflicts](https://www.postgresql.org/docs/18/explicit-locking.html).

Implementation refinement before final acceptance: follow awaits each metadata progress report. The CLI permits at most one 64 KiB report write and imposes a five-second write deadline, disposing blocked output rather than accumulating an unbounded console queue. Output failure cannot roll back an already committed source ACK; it terminates reporting with a nonzero result. Supplemental stream tests do not replace database/process-fault evidence.

## M2C.1 isolation correction — 2026-09-17

The original initialization argument omitted transaction-snapshot legacy writers. Real isolated reproduction m2c1-repro-20260916223953613-99f59788 at clean test commit 8ab152e5b687ca59528876faa773b921855ca17b confirmed the external code-derived schedule: source_writer snapshot 757:757: preceded privileged registration xid 758, held no outbox lock, and later committed entity/outbox 1:1 while seeing no binding in enqueue_capture. A fresh observer saw the committed binding, missing work and captureOnce's integrity stop, with no pipeline event or source ACK. This is later implementation evidence, not a reviewer-executed failure or a reinterpretation of the earlier tested READ COMMITTED schedules.

Forward migration 005 uses CREATE OR REPLACE on the existing source_owner-owned SECURITY DEFINER enqueue_capture, retaining its trigger identity, fixed pg_catalog,pg_temp search_path and ACL, with explicit PUBLIC revocation. An unconditional isolation check raises 25001 before any binding SELECT unless the source transaction is READ COMMITTED. The registration lock still coordinates supported writers, but cannot repair another transaction's old snapshot. Do not change the caller's isolation, silently skip work, rewrite migrations 001–004, or move checks solely into callers.

All state-changing legacy mutations now share this enforced isolation precondition. Read-only operations remain unrestricted by enqueueing, and a legacy unchanged update/repeated delete that creates no revision does not invoke enqueue_capture. execute_command retains its existing READ COMMITTED requirement even for no-op/replay receipts. The legacy interface's exclusion from command deduplication does not exclude its writes from capture. Migration changes no payload, event bytes, receipt, work row, binding, receiver identity or terminal ACK. Guarded installation and populated registered-M2C upgrade require exact independent before/after snapshots and real regression evidence. No sink or seed/activation work is authorized by this correction.
