# ADR 014: operational observations, local control and immutable replay

Date: 2026-09-20. Status: authorized pre-implementation design; execution pending. This implements the planned operational backend without changing canonical content or sink independence. Existing ADRs 005 and 009-013 remain authoritative.

## Composition and boundary

One Nest application under apps/control-api uses root package/lockfile. Its own TypeScript build enables legacy decorators and metadata; existing native Node scripts retain erasableSyntaxOnly. Pin @nestjs/common/core/platform-express 12.0.3 (controller/DI/runtime/official HTTP adapter), reflect-metadata 0.2.2 (decorator metadata), rxjs 7.8.2 (Nest's request pipeline), @nestjs/swagger 12.0.1 (actual-controller OpenAPI). Node 24.19.0 satisfies the published >=20 engine. No ORM, CLI scaffold, validation dependency or general dependency refresh. Use explicit bounded validators. No Swagger UI or other frontend assets/routes.

Require a run-local operator token for every mutation, compare without timing-dependent string equality, and bind the host Compose port only on 127.0.0.1. No CORS credentials, Docker socket, shell, SQL console, URL/proxy-name input, or production identity architecture. API startup performs no data/receiver initialization. Config is immutable for the process; credentials stay in private environment/file configuration, never returned or logged.

Controllers validate shape and translate status; services call domain facades or narrow operational functions. Each write has a fresh TransactionOwner/connection. Read transactions are read-only with explicit query/statement/connect deadlines. No shared concurrent transaction or network I/O inside a database transaction. The API owns no worker correctness state.

## HTTP v1

All JSON responses have request_id (validated incoming X-Request-ID UUID or generated UUID); the response header repeats it. Errors are `{request_id,error:{code,message}}` with stable sanitized code/message. 400 invalid_request, 401 operator_required, 404 not_found, 409 conflict, 422 integrity_block, 503 unavailable; unknown errors return 500 internal_error without raw causes. Body limit 8 KiB. Positive signed BIGINT identifiers remain decimal strings. UUID, enums and bounded cursors are validated before conversion. Unknown fields are rejected.

All mutations require Idempotency-Key UUID. New durable scheduling returns 202 with outcome accepted/scheduled; repeated original result returns 200 already_applied. A key reused with changed input is 409. Pause/resume keys are immutable operation identities: an old pause retry after a later resume never pauses again. Remote network PUT requests retain immutable requested state and completed observations; unresolved remote outcomes are reported unavailable and explicitly retried under the same key, never presumed rollback.

## Status and freshness

Each dependency observation has observed_at and fresh/stale/unavailable. A successful bounded read describes that observation, not atomic global time. Source DB clock is authoritative for due/delayed/lease states and oldest pending source-recorded timestamp. Pending includes every unacknowledged committed revision; due, delayed, leased and blocked are separate. A fresh empty source reports pending=0 and oldest_pending_at/age=null. Failed reads report unknown/null counts and unavailable; no cached zero. A timestamp older than the bounded freshness budget (30 seconds) is stale. Missing capture work is an integrity/data-health failure. Source backlog says nothing about unsent seeded baselines.

Sink target modes, actual receiver/proxy reachability and data failures are separate dimensions. ES pending/retry/leased/satisfied/dead_letter and oldest unresolved staging timestamp are explicit. Rabbit satisfaction means broker-confirmed only. Consumer processed/quarantined and pending observations are distinct. No end-to-end percentage before required membership is sealed; afterward expose exact string required/settled/pending/error counts by sink/consumer. Overall is unavailable when an authoritative dependency cannot be observed, degraded for blocks/errors/cooldown, otherwise healthy; backlog alone is not data corruption.

## Replay and retained history

Additive pipeline migration changes es_dead_letters key to (event_id,destination_id,attempt_id), preserving every old column/row/attempt identity. Guard completed failures against UPDATE/DELETE/TRUNCATE. Attempt pruning must exclude all retained failure/replay references. Backfill current-count joins must include the current terminal attempt so multiple historical failures cannot inflate membership; terminal run phase/completion time remain immutable.

Immutable replay_requests records caller UUID, fixed kind elasticsearch, bounded actor (local-operator), reason, target event/destination/generation/terminal attempt and requested_at. Immutable replay_items references the exact historical failure and records scheduled_at and original scheduling result. A single owned transaction arbitrates the request key, locks exact ES delivery, validates current dead_letter plus matching attempt and registered destination/generation, inserts request/item, then changes only that ES delivery to pending/due, clears current terminal/scheduling evidence, retaining monotonically increasing claim generation. The guard permits this transition only with the corresponding new immutable replay evidence in the same transaction. Already satisfied deliveries remain immutable. Identical key returns original scheduling result before inspecting newer state; changed request conflicts. Competing keys serialize on the delivery lock; stale attempts fail. No source ACK, canonical, Rabbit or consumer state changes.

A later mapping failure inserts a new immutable failure keyed by its new attempt. Receiver repair may permit the same event. OP07 uses a controlled temporary default ingest pipeline that forces an actual mapped-field rejection, then restores the original receiver configuration; the registered mapping/index/cluster/destination/generation stay unchanged. This avoids weakening the fixed search-v1 mapping or rebinding a receiver to make replay succeed. Source BUSINESS DATA repair uses a new command/version/event, tested separately. Consumer quarantine remains inspect-only/non-replayable; no raw-body republish route exists.

Durable operator command receipts wrap accepted backfill functions in the same pipeline transaction. Source fixture identity and receipt wrapper invoke the real source command function inside one source transaction, with restricted source_operator authority. Source successful command receipts remain authoritative under API death. Structured response/audit distinguishes scheduled, already_applied, conflict, unavailable and integrity/configuration blocks.

## Metrics contract

Custom text collector exports retained SQL facts directly; no in-memory Counter.set/reset fiction and no second metric library. Direct endpoint/restart/rate tests suffice; a Prometheus server is deferred to final packaging. HELP strings below are exact. All named snapshot metrics are TYPE gauge; all *_total are TYPE counter. Missing dependency values are omitted, accompanied by dependency health and missing freshness, rather than zero-filled.

Labels are allowlisted: sink elasticsearch/rabbitmq; state fixed domain state or healthy/degraded/unavailable; phase scanning/sealing/importing/draining/complete/complete_with_errors; kind elasticsearch/consumer; component source/pipeline/elasticsearch/rabbitmq/consumer; outcome_class applied/already_applied/superseded/mapping/oversized/transient/auth/configuration/integrity/expired/confirmed/historical_unknown; disposition applied/already_applied/superseded/dead_letter/broker_confirmed. Never IDs, free text, reasons, messages or run UUIDs.

Completed attempt outcome totals persist through bounded diagnostic pruning using a compact SQL aggregate updated transactionally on attempt completion. At migration, seed retained completed outcomes; classify already-pruned attempts as historical_unknown using claim generations minus retained attempts. In-flight attempts are not falsely completed. Staged/settled/effect/replay counters derive from immutable facts; repeated dead-letter outcomes count historically even after replay clears current failure. A historical unknown bucket admits the pre-instrumentation information boundary. Useful throughput is the rate of satisfied dispositions/consumer effects, separate from attempts and rejection rate. Counts in JSON are exact decimal strings; Prometheus scalar precision follows its numeric format. No timer continuously changes a recorded timestamp.

## Logs, recovery and acceptance

One bounded JSON line per completed HTTP operation: timestamp, level, service=control-api, operation (static route), request_id, outcome, duration_ms, stable error_class, and cleanup_error_count where relevant. No body, raw context, remote response, DSN, tokens or certs. Durable operation receipts preserve scheduling across process death before HTTP/logging. Correlation is retained in immutable audit, separate from caller idempotency identity. No rollback assumption after timeout/unknown COMMIT. Startup never resets claims, metrics, terminal evidence or runs.

OP01-OP18 are independent requirements in the milestone/inventory, committed before implementation. Tests require real databases, ES, RabbitMQ, Toxiproxy and process death/restart. Full prior bounded profiles run once per gate. No mocks replace these boundaries. Two clean gates and populated upgrade are required before claiming M6 acceptance; backend G5 preparation is not final UI G5.
