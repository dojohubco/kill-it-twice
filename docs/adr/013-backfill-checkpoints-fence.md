# ADR 013: current-state backfill with atomic progress and a finite source fence

Date: 2026-09-20. Status: authorized implementation design before production changes/tests. Refines ADR 004's already selected convergent model. No scale or full G1–G5 claim.

## Required set and identity

A caller UUID is the run identity and immutable request key. The request includes expected epoch, pipeline instance, codec and range count (default 4, maximum 16). Creation verifies the active source/capture binding and observes committed max(entity_id), U, with source clock/snapshot evidence. U=0 is valid. A matching retry retains the first committed U; changed caller parameters conflict. Pipeline creation records actual registered Elasticsearch/RabbitMQ destination IDs/generations and consumer/registration identities. Operational cooldown does not prevent scanning. Binding validation occurs in each actual pipeline work transaction. One partial unique index permits at most one unfinished run per pipeline instance.

R is the unique union of revisions actually observed and staged by this current-state scan and mutations visible in the retained source fence. Superseded, unobserved original baselines are not implicitly members. Later mutations remain capture work independently of this finite run. Backfill never writes source ACKs or turns baselines into outbox mutations.

## Additive source boundary

Source migration 007 introduces source_backfill (NOINHERIT runtime, no business/control-table DML), plus source.backfill_fences and source.backfill_fence_members. Header: run_id UUID PK, pipeline_id/source_epoch UUID composite FK capture_binding, codec fixed text, snapshot text, observed_at finite timestamptz, member_count nonnegative BIGINT, max_key nonnegative BIGINT. The final four fields are nullable only inside the creation transaction. Members: (run_id,allocation_id BIGINT) PK, epoch/entity_id/entity_version with outbox revision FK, unique(run_id,epoch,entity_id,version); no payload copy. Both tables are immutable after completion; a deferred header check rejects incomplete/count-mismatched creation. No per-member whole-fence recount trigger.

`backfill_source_identity` checks active lifecycle, registered exact pipeline/epoch/codec and PG18 UTF8, then returns bounded metadata/U. The new SourceReader current-page operation selects entity_id > cursor AND <= range_end ORDER BY entity_id LIMIT <=16, never OFFSET or row SKIP LOCKED. One coherent statement measures escaped payload text plus the established conservative 1024-byte envelope allowance. It conditionally transfers only the fitting prefix within 64 KiB/record and 256 KiB/page. Metadata for the next oversized boundary is bounded; it becomes an explicit block. Only the included prefix advances. A same-statement NOT EXISTS probe establishes EOF; a byte-short page does not imply EOF. Immutable fence reads use the same bounds, joined to exact outbox revisions. Payload numbers stay opaque PostgreSQL text.

`seal_backfill_fence(run,epoch,pipeline)` requires READ COMMITTED. INSERT header ON CONFLICT DO NOTHING serializes the key; a separate subsequent SELECT gets the committed winner. A new header executes one data-modifying CTE statement: record pg_current_snapshot()/clock_timestamp, INSERT SELECT every visible outbox identity without ACK/max/time filters, and finalize the header from inserted count/max. This statement defines the cut. The source transaction contains no business write/network operation. COMMIT makes the whole immutable set authoritative; death before COMMIT leaves nothing, death afterward recovers the same set. Allocation order is only a keyset order within this immutable set. A late smaller allocation committed after the cut stays outside it and is handled by live capture. Header/member storage and finite INSERT SELECT cost need later scale measurement.

Only allowlisted source functions and required reader columns are granted, with source_owner SECURITY DEFINER, qualified references, fixed pg_catalog,pg_temp search_path and PUBLIC revocation. No binding/seed/write permission is added.

## Pipeline persistence and SQL authority

Pipeline migration 006 adds pipeline_backfill, with CONNECT/USAGE and allowlisted functions only. Tables:

- backfill_runs: run UUID PK; immutable request/binding JSONB with bounded shape and exact decimal-string identifiers; U BIGINT >=0; requested partition count 1..16; source observation; phase scanning/sealing/importing/draining/complete/complete_with_errors; desired_paused boolean; bounded block code; immutable attached fence snapshot/count/max/time; created/sealed/completed times.
- backfill_ranges: PK(run,range_no), immutable lower/upper BIGINT, checkpoint BIGINT within bounds, state pending/leased/closed/blocked, owner UUID/generation BIGINT/lease deadline, next_eligible_at, bounded block reason, last_batch UUID. Scan ranges 1..N exactly partition (0,U]; U=0 has one explicitly empty closed range. Range 0 is the bounded import cursor over an attached immutable fence. Due partial indexes support SKIP LOCKED.
- backfill_batches: request UUID PK; run/range FK, owner/generation, previous/next cursors, EOF, immutable bounded item descriptors (source key, event ID, canonical hash; at most 16), observed source metadata, created_at. No payload copy. Exact retry compares descriptors AND authoritative ledger body bytes/hash, not a digest alone.
- backfill_members: PK(run,event_id), FK immutable events and first committed batch; immutable after insert. Overlapping scan/fence membership deduplicates here; each import batch still retains all of its bounded fence-key descriptors.

All BIGINTs are database BIGINT or application BigInt/decimal strings, never Number. Identity rows, batches and membership cannot be rewritten/deleted. Runtime cannot directly jump checkpoints. State/shape CHECKs explicitly reject NULL loopholes. A range-progress trigger ties each new checkpoint/closed state to its new batch, previous cursor and same claim. A deferred batch-local check verifies every descriptor's event/hash, run membership and obligations; no scan of prior batches is performed per event. Creation checks exact partition coverage once. Phase sealing checks closed ranges; import sealing checks cardinality and cursor continuity, with independent exact-set verification in tests. Source observation coverage is a trusted adapter invariant, not a cross-database FK.

## Transactions, clocks and pause

Use the accepted TransactionOwner exclusively; no pooling/retry/client exposure. Claim transaction: run FOR SHARE, validate binding/phase/pause, select one due range FOR UPDATE SKIP LOCKED, check clock_timestamp after locking, increment generation, persist fresh worker UUID/deadline, COMMIT. Default lease 30 seconds, renewal near 5 seconds through an independent short owner; validated shorter test intervals. Lost ownership cannot cancel an already-running source read, but cannot commit progress.

Page transaction lock order: run FOR SHARE, exact range FOR UPDATE, stable batch key, then events sorted by event_id. Validate unexpired current claim/cursor, call existing pipeline.stage_bound_event for every canonical input, insert/validate membership and immutable batch, update matching checkpoint/state, and check database clock again immediately before returning work. The deferred progress check also verifies the lease at transaction completion, so a deliberately delayed callback cannot commit expired progress. A staging/relation conflict rolls back the entire page. Matching committed batch retry is read-only and returns original evidence even after the old claim expires; it never advances twice. A new batch under stale ownership fails. Unknown COMMIT remains unknown; explicit identical retry or fresh checkpoint inspection resolves durable evidence.

Phase/pause/attach/completion operations take run FOR UPDATE, then ranges in numeric order if needed. Pages never upgrade their shared run lock: a separate short transition operation advances scanning to sealing when all ranges close. This avoids serializing network/source reads and avoids shared-to-exclusive upgrade deadlocks. Pause is durable admission control; current pages may finish. Effective paused means desired_paused and no unexpired range lease. Resume changes only desired admission. Transient failures release current claims with persisted positive jitter (existing 1s base/30s cap); lost connectivity leaves expiry. Oversize/integrity leaves bounded visible blockage at the exact unresolved cursor. Other ranges may continue; no automatic skip/repair.

Fence attachment happens only after source owner returns confirmed COMMIT. It validates the same run/binding and retains the immutable source header, then creates range 0. Each bounded import page uses the same atomic staging/membership/batch/progress operation. Its ordered keys must belong to the retained source fence, supplied through the trusted bounded source adapter. Import completion counts actual descriptor membership against the attached cardinality; verifier compares exact source/pipeline sets. No source transaction spans pipeline work. Finished import freezes R and enters draining.

## Completion and reporting

Completion uses run membership LEFT JOIN events, both intents/destinations/terminal attempt evidence and consumer observations. Missing/mismatched canonical/relation/binding evidence blocks, never disappears from a denominator. Existing ES witness/disposition and attempt evidence must match; higher valid witness may be outside R. Rabbit requires confirmed attempt/channel/local settlement. Consumer requires exact matching bytes/hash and registered processed receipt. Pending/leased/retry remains draining. Only all-terminal R permits complete; terminal ES dead_letter or consumer quarantine gives complete_with_errors. A completed run and its R never grow/reset. Post-fence capture remains independent.

Status returns one bounded run, at most 17 range summaries, decimal counts, source/pipeline observation times, fence/import state and block codes. No pre-seal exact percentage. CLI start/status/pause/resume/once/follow uses explicit credentials and identities, one page in flight, bounded awaited output and graceful admission stop. Source backlog zero does not mean baselines were replicated. SQL checks local evidence; remote reads/ACK sequencing retain the existing trusted adapter assumptions.

## Verification and remaining scope

Independent BF01–BF17 plus healthy controls are committed with this decision. Actual SQL/session/clock observations, two scanner processes, SIGKILL, real capture and both receivers test the stated boundaries. The independent oracle uses declared seed recipe/map, mutation journal, exact source fence and retained receiver/effect evidence, not production progress counters alone. Synthetic/privileged negative controls are labeled and isolated. Known seed per-row deferred validation/history queries and all-history status costs need later measurement; these are existing observations, not future discoveries. No UI/API, capacity claim or full G1–G5 acceptance.
