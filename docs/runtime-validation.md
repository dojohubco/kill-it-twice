# Retained runtime validation

This bounded integration check exercises the root Compose application rather than renaming historical milestone tests. It does not establish the two-million-record capacity profile or final G1-G5 acceptance.

The current continuation begins with the existing uncommitted runtime draft and its isolated developmental installation. That draft is retained. A read-only input manifest/patch records the actual starting content; it is not represented as previously committed or accepted code.

## Required checks

- R01: cold initialization creates distinct source/state databases, the independent consumer database, authenticated retained receivers, restricted per-role configurations and one loopback gateway. No worker mounts setup credentials or a Docker socket.
- R02: explicit bounded seed and identical repetition preserve baseline identity/time/payload; a conflicting count rejects. Seed activation/scheduled backfill is not delivered completion.
- R03: the actual separate workers discover and converge the baseline and a verifier-declared source mutation sequence. Source commands are not replaced with direct fixture DML. The complete immutable event set and current state are independently compared, including a tombstone and harmless repeated command.
- R04: a real worker SIGKILL and retained full Compose down/up preserve the registered identities, baseline/command results, event content, mutation effects and delivered state. Only run-owned test resources are faulted and cleaned.
- R05: a real browser reads the built Angular interface through the normal gateway/API and inspects a real record; no intercepted response fixture or live-data fallback is present.
- R06: runtime process/memory/port/configuration restrictions are inspected, source/pipeline/consumer and receiver exports agree, and missing/extra/altered records are detected by the offline verifier's negative controls.

## Oracle and evidence

The verifier declares seed recipe/count and source commands before executing them. SQL exports retain exact JSONB text and string identities in bounded pages. An independent Python/SQLite checker reconstructs the canonical envelope and expected current history without importing production normalization or completion queries. Payload values use Decimal/int rather than floating-point parsing. Exports occur after the fixture is quiescent; separate database snapshots are not an atomic global snapshot.

A successful bounded check records actual commands, exit codes, code/input identity, expected input declarations, read-only exports, observed receiver state, restart equality, real process exits, browser evidence and cleanup. Developmental dirty-tree runs are labeled as such; final evidence refers to committed code. All artifacts remain local until explicitly published. Failed checks and original capture provenance remain unchanged.

The default validation fixture is 257 baselines with a small declared mutation sequence. This deliberately proves packaging/recovery behavior quickly. Final integrated fault gates and a separately measured scale profile remain outstanding and must never be inferred from this count.
